# 引継書・提案書の確認事項

実装中に見つかった、資料間の不一致や前提の要確認点。

1. **Gサイズ筐体の長さ**: 引継書は「全長約368mm」、提案書 §6 は「長さ約91cm」。`constants.py` は引継書の値で仮置き。
   アンテナ展張機構・電源容量の制約パラメータに効くので確定が必要。
2. **Dubins 語「LSC」**: 引継書 §3 の「LSC, RSR 等」は LSL の誤記と解釈し、標準 6 語（LSL,RSR,LSR,RSL,RLR,LRL）を実装。
3. **ブイ網による補正の基準**: ブイの絶対位置を HF 地表波で決める限り、HF の系統誤差（伝搬遅延 / ASF）は
   ブイと航空機に共通に残り、ローカル DGPS のような差分補正にはならない。真の差分補正には位置既知の基準
   （沿岸の既知点モニタ局、投下時点の高精度位置など）が要る。どれを前提にするか決めたい。
4. **「ナノ秒同期」と精度目標の整合**: 1 ns ≒ 0.3 m。3〜6 kHz 帯域の包絡線相関では CRLB でも数十〜百 m
   （数百 ns）程度。ns 級は搬送波位相の整数不確定性が解けた場合のみ。シミュレータではブイ同期誤差を
   距離換算 30 m（`vhf.buoy_sync_sigma_m`）で仮置き。
5. **精度の数値**: 本シミュレータの既定パラメータでは 50〜150 m 級となり、提案書の CEP 1〜2.5 km
   （100 km 視程時）より大幅に楽観的。HF SNR・ASF 残差・マルチパスの実測値で校正すること。
6. **ゼロ・モディフィケーションと LiteLLM**: 引継書 §1 は LiteLLM を「ソフトウェア・プロキシ」として
   ゼロ・モディフィケーションの手段に挙げているが、LiteLLM は LLM API のゲートウェイで、
   ソノブイ通信フォーマットの互換性担保とは別レイヤ。本実装では LLM 状況解析の経路としてのみ使用。
7. **aqua-drift-simulator（連携済み・確認事項あり）**
   - リポジトリに LICENSE が無いため、コードは複製せず `pip` の任意依存（git 参照）として取り込んでいる。
   - aqua の潮流場は時間一定のアフィン場（潮汐の時間変動なし）で、観測者は潮流のみで流れる（風圧流・拡散なし）。
     海面に浮く PNT RF ブイは風を受けるので、`drift.aqua.leeway` と `drift.diffusivity` を追加項として用意した（既定: 風圧流 0、拡散 5 m²/s）。
   - 投下補正で使う着水点は「ブイ初回 HF 測位相当（σ100 m）」で観測できる前提。放出位置は真値を使っており、
     GPS 拒否下では機体の推定位置誤差がここに乗る（未反映）。
   - aqua の layer/route（投下点への経路計画）は ASW 観測者用。PNT ブイ計画は本プロジェクトの Dubins プランナを使い、
     両者の統合（横風補正を経路に反映）は今後の検討事項。
8. **ブイ中心構成（2026-10-28 確定）で新たに効く点**
   - 受信周波数は母機が UHF コマンドで指示し、SDR は指示された複数の周波数を同時に受信する（2026-10-28 確定）。
     局ごとの周波数が 3〜30 MHz に散らばるので、3〜30 MHz を直接標本化する SDR か、複数の受信チャネルが要る
     （RTL-SDR は帯域 2.4 MHz で 1 チャネル）。電力は G サイズ筐体・稼働 8 時間の電池で賄えるかの確認が必要。
     母機が離れて指示が途切れると、MUF の変化（特に日没・日の出）で受からない局が出る。
   - UHF TOA（ブイで母機のコマンドの到着時刻を計測）と VHF TDOA（母機で到着時刻差を計測）の精度は仮定（30 m / 60 m）。
     既存のソノブイ受信機・コマンド送信機で時刻を精密に扱えるかの確認が必要。
   - 母機の絶対誤差は「ブイ網全体のずれ」で決まり、ずれの原因は全ブイに共通な電離層誤差。ブイを増やしても減らない。
     減らすには時間平均（相関時間）、送信所配置の改善、位置既知の基準（GPS が使えるうちの投下など）が要る。
